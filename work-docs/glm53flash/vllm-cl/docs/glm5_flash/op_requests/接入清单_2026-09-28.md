## 本轮接入明细

### #01 / #02 KDA 短卷积 prefill + decode（`vllm_cl/patch/patch_kda.py`）

新 ABI（算子组 2026-09-24 修复版，与旧结论不同）：

| 项 | 新算子要求 | 模型侧现状 | 适配动作 |
|---|---|---|---|
| `conv_state` | `[S_slot, state_len, D]`（SD，D 连续），**原位写回** | 传入的是 `[S, D, state_len]`（层内 SD→DS 的 `transpose`） | `.transpose(-1,-2)` 转回 SD（零拷贝 view） |
| `weight` | `[4, D]` **fp32**（传 `[D,4]` 会报错） | `_merged_conv_weight` 是 `[D,4]` fp32 | **加载期一次性转置**（见下），forward 不再转置 |
| `qkv` | bf16，prefill `[N,D]`；update `[B,T,D]`/`[B,D]` | prefill 传 `[D,T]`；decode 传 `[B,D]` | prefill 转置；decode `unsqueeze(1)` |
| `has_initial_state` | int32 | bool | `.to(int32)` |
| 返回值 | 单个 `out` | — | prefill 转回 `[D,T]`；update 还原原形 |
| 空槽 | prefill 对非空行的负槽位 **Assert**；update 跳过 `-1` | prefill 上游约定不会给非空行 `-1` | prefill 侧 `clamp_min(0)` 兜底（防 poison 设备），语义等价 null slot |
| bias | **不支持** | GLM5 三个短卷积 `bias=False` | 有 bias 时自动回退 native |
| spec/MTP | 本阶段不做 | 只用 plain decode | `query_start_loc`/`num_accepted_tokens` 存在时回退 native |

**权重转置前移到模型加载期**（2026-09-28 补）：新算子要求 `weight` 是**已转置**的 `[4, D]` fp32，
pytorch 侧已删除原先 wrapper 里的 `transpose`，因此插件在权重加载完成时一次性完成转换：
`patch_kda._install()` 给 `Glm5NextLinearAttention` 的 `q/k/v_conv1d` 打标记 →
`patch_linear` 的 `UnquantizedLinearMethod.process_weights_after_loading` 钩子调用
`prepare_kda_conv_weight`：拼接出 `_merged_conv_weight`（`[3D,4]` fp32）并生成转置后的
`[4,3D]` fp32 登记进 adapter 缓存，forward 直接命中、零转置。若某层形状不符合预期
（非 `[D,1,4]`），自动退回 forward 内的一次性懒转换，不报错。

开关：`DLC_KDA_CONV_PREFILL_OP` / `DLC_KDA_CONV_UPDATE_OP`（默认 `new`，设 `native` 即回退旧组合实现）。

真机验证（`tests/test_glm5_op_integration.py`，dlc:4，D=3072、分页非连续 state 视图）：
- decode：`state` 与 native **逐位一致**，输出最大差 1.2e-4（单元素，<1 bf16 ulp）；
- prefill：`state` 逐位一致，输出差 <5e-2（native 在 fp32 累加、算子走 bf16 通路，数 ulp）；
- `-1` 槽位：输出全 0、state 不变，与 null slot 语义一致；
- 性能（算子组实测，见 `02_dlc_kda_causal_conv_update.md`）：1509 槽位 0.06 ms vs 现有 `_causal_conv1d_update` 0.26 ms，
  且 wrapper 无 host 同步、可被 `DLCGraph` 捕获。

### #18 KV / state 整页清零（`vllm_cl/patch/patch_kv_block_zeroer.py`）

- `dlc_vllm_zero_block_ids_(seg_addrs int64, block_ids int32, n_blocks, n_segs, page_size_el, num_blocks_total)`
  的寻址是 `seg_addr + block_id * page_size_el * 4`，因此**同一调用内所有段的页大小必须一致** → 按「每块字节数」分组，逐组调用。
- 段地址在 `init_meta` 一次性算好：Attention 类按 `block_dim` 逐块（`ratio` 个物理块算作一页）；Mamba 类按底层
  storage 去重、以**整页**为段（conv 段与 recurrent 段同页，避免把 recurrent 的页步长当成页大小而越界清零）。
- 前提不满足（块内不连续、页非 512B 倍数、页大小冲突、地址未对齐）的张量自动落回原 PyTorch fancy-index 路径。
- 开关：`DLC_KV_ZERO_OP`（默认 `dlc`，设 `pytorch` 回退）。
- 真机验证：4 类几何（MLA full / KPool / Mamba 整页 / ratio=2 虚拟块）与 PyTorch 兜底**逐字节一致**，
  非稠密布局正确走兜底。

### #12 512-NoPE MLA cache 写入（`vllm_cl/attention/sparse_mla.py`）

- 真机验证：kpe=0 与 kpe=64 均逐元素一致，`-1` slot 正确跳过，未写行保持为 0。

### #04 KDA recurrent decode（`vllm_cl/patch/patch_kda.py`）

- 接线点 `fused_recurrent_kda_dlc`：先试 `_recurrent_decode_new_op`（`torch.dlc_kda_recurrent_decode`），
  不满足契约或算子缺失时落回 `_run_kda` native，行为不变。
  只承接模型 plain decode 分支的实际形态（`compute_gate=True` / `sigmoid_beta=True` /
  `use_qk_l2norm=True` / `lower_bound==-5.0` / bf16 / 有 `a_log`+`g_bias` / 无 `num_accepted_tokens`）。
- **state 布局**：算子组 2026-09-24 统一为 `[S_slot, H, Dv, Dk]` fp32 原位写回；拆池后每个池本就连续、
  offset==0、每行 512B，直接即可传入。
- **PAD_SLOT_ID(-1) 归一成 0**：kernel 对 slot 0 输出全 0、state 不写回，与 native `if idx < 0: continue`
  语义一致；负值直传会触发 kernel 内 Assert 并 poison 设备。
- **view 操作数物化（关键）**：模型 decode 的 q/k/v 来自 `qkv.split(...).reshape(1,-1,H,D)`、`raw_g` 来自
  `f_b_proj(...).reshape(...)`、`beta` 来自 `beta_raw.unsqueeze(0)`，都是 view。它们的 torch stride 往往
  「看起来合法」（N==1 时 q 甚至 `is_contiguous()`==True、offset==0），但底层 storage 的最低维是整条宽度，
  物理行不是 kernel 要求的 512B。Python 侧看不到 storage 的 `dlc_dim0_`/`dlc_layout_`，无法可靠判断
  dlc-contiguity，故 `_fused_operand` 对 q/k/v/raw_g/beta 统一 clone 成独立连续张量（decode 单步每层仅几 KB）。
- 开关：`DLC_KDA_RECURRENT_DECODE_OP`（默认 `dlc`，设 `native`/`0` 回退）。
- 真机验证：8 worker × 34 层 decode 全部命中算子、**零 fallback**，`kda_recurrent_op` 0.49–0.60 ms/call
  （34 层 ~17–20 ms/步）；单请求与 3 并发批解码输出均正确；`tests/test_glm5_kda_recurrent_decode_op.py`
  17 例（含模型 view 形态物化、PAD slot、`num_accepted_tokens` 快照、out 原位复用）全部通过。

### #11 512-NoPE 稀疏 MLA（`vllm_cl/attention/sparse_mla.py` + `vllm_cl/_custom_ops.py`）

- 接线点 `PyTorchMLASparseImpl._forward_bf16_kv`：`native_nope`（`cache.shape[-1] == kv_lora_rank`）
  分支由 `_forward_native_nope` 改为 `dlc_ops.sparse_attention_nope`，
  即 `torch.dlc_sparse_attention_kv_cache`（**直接读分页 cache**，不再走 576 布局的「先 gather」）。
- 与 576 路径的区别：576 需要把 cache 按 topk gather 成 `[T,K,576]` 再调 `dlc_sparse_attention`；
  512-NoPE 直接把 `[num_blocks,256,512]` 的 cache `view(-1,512)` 交给算子，算子内部按 topk 取数。
- 前置条件（不满足回落 native）：`q` 3-D / `q.shape[-1]==kv_lora_rank` / heads ∈ {2,4,8,64} /
  topk 宽度 ∈ {256,512,2048,2176} / `q`、`topk`、cache 均连续 / bf16 + int32。
- topk 宽度真相：config `index_topk=2048`、`index_kpool=4`，索引器写 2051 列，模型按
  `ceil(2051/128)*128 = 2176` 分配缓冲（`glm5next/nvidia/model.py:595-600`），**运行时永远是 2176**；
  尾部 125 列由 indexer 的整缓冲 `fill_(-1)` 保持为 `-1`，不会被读成有效槽。
- 开关：`DLC_SPARSE_MLA_NOPE`（默认 `1`，设 `0` 回退 native 组合实现）。
- 验收：`tests/test_glm5_sparse_mla_nope512_op.py` 8 例（decode/prefill/TP1-h64/尾部 padding/
  ABI 回落）；与 native 参考 `max_err ≤ 2e-2`（bf16 量级）。实测 Q=2048/H=8/K=2176：native 2011 ms
  → 算子 **31 ms**；Q=1 decode：126 ms → 0.6 ms。

## 已接入：#13 `dlc_mhc_pre` + #14 `dlc_mhc_post`

- 接线点：`vllm_cl/patch/patch_mhc.py`。`MHCPreOp` / `MHCPostOp` / `MHCFusedPostPreOp`
  三个 `forward_oot` 全部切到 DLC 算子；`DLC_MHC_OP=native` 可整体回退。
- 关键契约：`torch.dlc_mhc_pre` 返回 **flat** `post_mix [N,hc]` / `comb_mix [N,hc*hc]`，
  插件统一 reshape 回 native 的 `[...,hc,1]` / `[...,hc,hc]`，下游无感知；
  `torch.dlc_mhc_post` 要求 `comb_res_mix` 为 flat `[N,hc*hc]`。
- 子层 RMSNorm 进 kernel：插件不再在外层补 `_rms_norm`，少一次 `[N,4096]` 读写。
- 不做 N 阈值切换：native 组合在 DLC 上是 host 瓶颈（每条 Sinkhorn/einsum 拆成几十个小 op），
  实测 dlc:0、hidden=4096 下 kernel 在所有 N 都更快（pre 1.7x@4096 ~ 26.7x@1，
  post 47.9x@4096；N=4096 绝对值 pre 20.2 vs 35.1 ms、post 4.5 vs 213.6 ms）。
- 核对：`tests/test_glm5_op_integration.py::test_mhc_*`（4 组几何 × dlc/native 双分支 + post + fused）。
