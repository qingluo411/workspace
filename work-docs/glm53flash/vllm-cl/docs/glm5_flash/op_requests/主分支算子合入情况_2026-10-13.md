# GLM-5.3-Flash 算子「主分支合入情况」梳理（2026-10-13）

> 目的：算子组此前交付的算子都落在临时/特性分支上。本文对照 `op_requests/` 里的 19 条需求
> （#08 已撤销，实为 18 条），核查 **DLC_Custom_Kernel 主分支** 与 **pytorch 主分支** 上
> 到底有没有、是哪一版，供决定「直接切 main」还是「需要 cherry-pick / 合分支」。

## 0. 核查范围与判定方法

| 项 | 值 |
|---|---|
| DLC_Custom_Kernel | `main` = `a53a17fb4`（2026-10-12，「add FP32/BF16 FFT kernels」），与 `origin/main` 一致 |
| pytorch | `main` = `67e07b04fa`（2026-10-10，「remove copy transpose in kda_causal_conv_update」），与 `origin/main` 一致 |
| 运行期实测 | `/root/workspace/.venv/bin/python -c "import torch; hasattr(torch, ...)"`（torch 2.5.0，主分支编译产物）|
| kernel 侧 | `git ls-tree main` + `dlc_src/enabled_kernels.hpp`（由 `kernel_info.yaml/kernel_dispatch.yaml` 生成，即实际编进 `libcustom_dlc_perf_lib.so` 的清单）+ `build/dlc_src/*.o` |

判定口径：**「主分支有」= kernel 主分支有源码且 `enabled_kernels.hpp` 里为 `DLC`（或 CPU 回退），
且 pytorch 主分支 `native_functions.yaml` 注册了对应 `dlc_*` op，运行期 `hasattr(torch, ...) == True`。**
只满足一半的，单独标出。

## 2. 分类明细

### A. 主分支完全可用（4 条）
- **#12 `dlc_vllm_concat_and_cache_mla_`**：kernel `custom_concat_and_cache_mla`/`_bf16`；
  pytorch `native_functions.yaml:595`，运行期 `hasattr(torch,'dlc_vllm_concat_and_cache_mla_')` = True。
- **#14 `dlc_mhc_post`**：kernel `custom_mhc_post`；pytorch `native_functions.yaml:476`。
- **#17 `dlc_fused_q_kv_rmsnorm`**：无独立算子，插件用两次 `dlc_fused_rms_norm_f32_bf16`（kernel+pytorch 均有）。
- **#18 `dlc_vllm_zero_block_ids_`**：kernel `custom_zero_block_ids`；pytorch `native_functions.yaml` 已注册。

### B. 主分支是「基础/旧版本」，算子组后续修复或扩展未合（5 条）
- **#01 `dlc_kda_causal_conv_prefill`**
  - 主分支 kernel：`dlc_kernels/conv/kda_causal_conv/kda_causal_conv_prefill.c`（旧版，整条序列驻留 VMEM，
    无 token 分块），提交 `40ddc7e7e perf: #7752` 为最后一版。
  - 缺 `#7949 fix: resolve kda_causal_conv_prefill stuck`（`db6e67510` / `22931927e`，分支
    `jinxing_fix_7949_260924`、`test-glm53flash`）。→ **主分支上 N≥3072 仍有卡死风险。**
  - ABI 已是对齐新版的（`weight [4,D]`、`conv_state [S_slot,state_len,D]`），pytorch 主分支 wrapper 也按此校验。
- **#02 `dlc_kda_causal_conv_update`**
  - 主分支 kernel 仍是每次调用 `HBM2VMem(hbm_conv_state, ..., state_slots * state_len * ...)` 搬整池
    的旧实现（`kda_causal_conv_update.c:109`）。
  - 缺 `#7950 perf: optimize ..., del big dma`（`1518c8d50` / `3c6a37d41`，分支
    `jinxing_perf_7950_260924`、`test-glm53flash`）。→ **主分支上仍是随槽位数线性变慢的慢版。**
- **#09 `dlc_kpool_mqa_logits`**
  - 主分支 kernel `custom_kpool_mqa_logits_bf16`（`b599e152e feat:#7956`）+ pytorch op 均有；
    但只是「pooled_keys 已备好」的基础打分形态。
  - 2026-10-09 的扩边界 `dlc_kpool_select_topk`（池读出 S4 + topk S6 + 展开 S7）在主分支**没有任何实现**
    （kernel 仅在 `chiyao-dev1` / `chiyao-dev-vllm-kpool-expand-topk`）。
- **#11 `dlc_sparse_attention_kv_cache`**
  - 主分支有基础 `custom_sparse_attention_kv_cache_bf16[_h2/h4/h8/h64][_topk*]` 与 pytorch op。
  - 缺 512-NoPE 专用家族 `..._nope_bf16_*`（#7958，`3509ee461`，只在 `test-glm53flash`）
    与 `#8015 sparse_attention_kv_cache prevent NaN`（`131b27887`，分支 `heiqi_sparse_attn_kv_cache_nan`）。
  - 主分支 `git ls-tree main | grep nope` 只有 `vllm_deepseek_nope_rope`，无 sparse nope 文件。
- **#13 `dlc_mhc_pre`**
  - 主分支有基础 op，但 `dlc_kernels/vllm/mhc_pre.cpp` 中 `norm_weight|norm_eps` 出现次数 = **0**
    （`test-glm53flash` 版 = 15）。
  - 缺 #7959（`57ee4d343` / `323a0ae89` / `d698fa0fb`，分支 `feat/custom-mhc-pre-norm-perf`）。

### C. kernel 已合入主分支，但 pytorch 主分支没有注册对应 op（无法调用，3 条 + #04b）
> 这是「看起来有、其实用不了」的一类：`libcustom_dlc_perf_lib.so` 里有 kernel，但 `torch.dlc_*` 不存在。

- **#03 `dlc_kda_chunk_prefill`**：kernel `custom_dlc_kda_chunk_prefill` ✅；
  `hasattr(torch,'dlc_kda_chunk_prefill')` = **False**（pytorch 实现在 `test-glm53flash`，`752bb8d80f`/`ea372b928f`）。
- **#04 `dlc_kda_recurrent_decode`**：kernel `custom_dlc_kda_recurrent_decode` ✅；
  `hasattr(torch,'dlc_kda_recurrent_decode')` = **False**（pytorch 在 `test-glm53flash`，`5919e6d2d1`/`c424c65b6e`）。
- **#06 `dlc_kda_rmsnorm_sigmoid_gate`**：kernel `custom_kda_rmsnorm_sigmoid_gate_bf16` ✅；

## 5. 对「当前 main 编译环境」的直接影响

1. **KDA 三件套（#03/#04/#06）当前完全不可用**：kernel 编进了 `.so`，但 pytorch 没有 `torch.dlc_kda_chunk_prefill` /
   `dlc_kda_recurrent_decode` / `dlc_kda_rmsnorm_sigmoid_gate`。插件若按 `test-glm53flash` 的写法调用，
   会直接 `AttributeError`，回退逻辑只有在显式 `hasattr` 时才会兜住。
2. **#01/#02 虽然可调用，但用的是算子组修复前的版本**：prefill 有卡死风险、update 有整池 DMA 性能回退。
   这与 2026-09-28 复测结论（prefill 通过、update 0.06ms）不一致——那些结论基于 `test-glm53flash`。
3. **#05/#07/#09扩展/#10/#15/#16/#19/#04b 需要算子组把实现合入 main，或适配组临时 cherry-pick**，
   否则 vllm-cl 插件主路径只能继续走 native 回退。
4. 需要确认 pytorch 主分支 `dlc_mhc_pre` 是**无 `norm_weight`/`norm_eps` 的旧签名**（`native_functions.yaml:471`
   只有 `rms_eps/hc_pre_eps/hc_sinkhorn_eps/hc_post_mult_value/sinkhorn_repeat/n_splits`），
   插件按新签名（带 `norm_weight`/`norm_eps`）调用会报错。

## 6. 建议动作（供参考）

1. **先合 `test-glm53flash`（两侧）到 main**：一次性补齐 #01/#02 修复、#03/#04/#06 的 pytorch 绑定、
   #05/#10/#11/#13。这是收益最大的一步。
2. **再逐条取以下分支**：`jinxing_feat_7946_261008`（#07）、`jinxing_feat_8087_261012`（#07扩展）、
   `chiyao-dev1`（#09扩展）、`feat/generation-prod-7960`（#16 kernel）、`lima_feat_8092_261010`（#19 kernel）、
   `jinxing_kpool_append`（#07 pytorch）；#16 的 pytorch 侧、#15、#19 的 pytorch 侧、#04b 尚无交付。
3. 合入后重跑两侧检查：kernel `enabled_kernels.hpp` 新增对应 `DLC` 项；pytorch 重跑第 3 节脚本确认 `hasattr` 为 True。
4. 若短期无法合 main，建议 vllm-cl 插件对所有新算子保留 `hasattr(torch, 'dlc_xxx')` 判定并回落 native，
   避免在 main 上直接抛 `AttributeError`。
