# Kimi K3 适配 DLC：GLM-5.3-Flash 算子复用分析（2026-10-13）

> 对照对象：`docs/glm5_flash/op_requests/` 里为 GLM-5.3-Flash 实现的 19 条算子
> （含已合/未合主分支的全部），逐条判断能否用到 Kimi K3。
> 依据：K3 官方 `config.json` + `modeling_kimi_linear.py` / `modeling_kimi_k3.py` 源码（ModelScope 实拉），
> 以及 GLM-5.3-Flash 的 `config.json` 与算子需求文档。

---

## 0. 结论摘要

- **能直接复用**：**KDA 全家桶（#01~#06）+ MLA cache 写入（#12）+ cache 清零（#18）**。
  K3 的 KDA 代码与 GLM5 **几乎一模一样**（同一套 FLA `chunk_kda` / `fused_recurrent_kda` /
  `FusedRMSNormGated` / `ShortConvolution`，同样 `short_conv_kernel_size=4`、`gate_lower_bound=-5.0`、
  `use_qk_l2norm` / `use_gate` / `use_beta_sigmoid` 全开、`safe_gate`）。这是复用价值最大的部分。
- **需适配/扩展**：KDA chunk/decode 要覆盖 K3 的 **H=96、D=12288、hidden=7168**；
  fused MoE 可复用但**激活要从 silu/swiglu 换成 SiTU，并加 Latent MoE 的前后投影 + norm**。
- **完全不可复用**：**KPool/DSA 全家桶（#07/#09/#10/#19）**、**mHC 全家桶（#13/#14/#15）**、
  **512-NoPE 稀疏 MLA（#11）**、**clamp SwiGLU（#16）**。K3 没有 KPool、没有 mHC，
  MLA 是**稠密 Gated MLA**（带 rope + 输出门），激活是 **SiTU-GLU**。
- **K3 新增、GLM5 完全没有的**：**Attention Residuals（AttnRes）**、**Latent MoE**、
  **SiTU-GLU**、**MLA 输出门 + q LoRA**、**MoonViT3d 视觉塔**。这些要么新算子，要么 native。

## 1. K3 与 GLM5 的子系统对照

| 子系统 | GLM-5.3-Flash | Kimi K3 | 是否同源 |
|---|---|---|---|
| 线性注意力 | KDA，34 层，H=64，D=128，conv=4，lower_bound=-5.0，o_norm=sigmoid gate | KDA，69 层，**H=96**，D=128，conv=4，lower_bound=-5.0，o_norm=sigmoid gate，`use_full_rank_gate=true` | ✅ **同一套代码** |
| 全注意力 | KPool-DSA **稀疏 MLA**（11 层），qk_nope=256、qk_rope=0、v=256、kv_lora=512，`index_kpool=4`、`index_topk=2048` | **稠密 Gated MLA**（24 层），qk_nope=128、qk_rope=64、v=128、kv_lora=512、q_lora=1536、**output gate** | ❌ 不同（稀疏 vs 稠密 + 门控） |
| 残差结构 | **mHC（hyper-connection）** 四路残差混合 + Sinkhorn | **Attention Residuals（AttnRes）**：每 12 层一个 residual bank，RMSNorm 打分 softmax 加权 | ❌ 不同机制 |

| 激活 | `silu` + `swiglu_limit=10`（clamp） | **`situ`（SiTU-GLU, beta=4 / linear_beta=25）** | ❌ 不同 |
| 视觉 | GLM4.1V 视觉塔，有 vision Q/K RMSNorm（#17） | **MoonViT3d**，`norm_type=rmsnorm`，未见 q/k norm | ❌ 不同（#17 大概率不适用） |
| 量化 | 官方 block-FP8；DLC 用 AWQ W4A16 | 官方 MXFP4/MXFP8（QAT） | 见 `01_量化调研` |
| 词表 | — | 163840 | — |

## 3. K3 新增、GLM5 完全没有的模块（需要新算子或 native）

### 3.1 Attention Residuals（AttnRes）

```python
# 每层两张 [num_tokens, num_blocks+1] 的 softmax 权重，对 residual bank 加权求和
def _apply_attn_res(prefix_sum, block_residual, proj, norm):
    v = cat((block_residual, prefix_sum.unsqueeze(1)), dim=1)   # [T, B+1, H]
    k = v.float() * rsqrt(v.float().pow(2).mean(-1, keepdim=True) + eps)
    scores = (k * (norm.weight * proj.weight.squeeze(0))).sum(-1)
    probs = scores.softmax(-1)
    return matmul(probs.unsqueeze(1), v.float()).squeeze(1)
```

- 每 `attn_res_block_size=12` 层写入一次 residual bank；每层 attention 前后各做一次 `_apply_attn_res`
  （4 个 `Linear(hidden,1)` + 4 个 RMSNorm）。
- **不是 mHC**：没有 4 路 `hc` 维度、没有 Sinkhorn。GLM5 的 `dlc_mhc_pre/post` **不能直接套用**。
- 是否值得新算子，取决于 profile；首阶段可以先用 native（等价于几次 RMSNorm + 小 MatMul + softmax）。

### 3.2 Latent MoE

```python
if use_latent_moe:                      # routed_expert_hidden_size = 3584
    hidden_states = routed_expert_down_proj(hidden_states)     # 7168 -> 3584
# ... fused MoE（expert 在 3584 维度上做 3584x3072 的 FFN）...
if latent_moe_use_norm:
    y = routed_expert_norm(y)           # RMSNorm(3584)
y = routed_expert_up_proj(y)            # 3584 -> 7168
y = y + shared_experts(identity)        # 2 个 shared expert
```

- 对 DLC 的 fused MoE 内核是**结构级变化**：要在 expert bank 前后各包一层 GEMM + 一个 RMSNorm，
  或者把它们融进内核。GLM5 的 MoE 没有这层。

### 3.3 SiTU-GLU 激活

```text
situ_a = beta      * tanh(gate / beta)      * sigmoid(gate)     # beta=4
up'    = linear_beta * tanh(up / linear_beta)                   # linear_beta=25
out    = situ_a * up'
```

- GLM5 的 `dlc_silu_and_mul_with_clamp` 只做 `silu(clamp(gate)) * clamp(up)`，语义不同。
- K3 的 **dense MLP、shared expert、routed expert** 全用它 → 需要一个新的 `situ_and_mul` 算子
  （或先 native），并让 fused MoE 支持 `activation=situ`。

### 3.4 Gated MLA（稠密）

- 标准 DeepSeek-style MLA（q LoRA 1536 → q_nope 128 + q_rope 64；kv_a 512+64；v 128），
  **额外有输出门** `g = sigmoid(g_proj(hidden))` 再乘 attention 输出。
- GLM5 的 #11 是针对 KPool 稀疏 MLA 的，**不适用**。DLC 现有的稠密 MLA 内核
  （`paged_flash_mla_bf16` 系列）可作为基础，但要补 **输出门**，并核对 K3 的
  head dim（q 192 / v 128）与 rope 布局。

### 3.5 Vision（MoonViT3d）

- `vt_hidden_size=1024`、12 heads、27 层、patch 14、`patchmergerv2` 投影。
- 与 GLM5 的 GLM4.1V 视觉塔不同，需单独评估。

## 4. 对 GLM5 算子工作量的结论

1. **KDA 这条线（#01~#06 + state pool）几乎是为 K3 提前做好的**，是本次适配最大的复用红利。
   唯一需要确认的是 **形状覆盖**：K3 的 H=96、D=12288、hidden=7168 是否落在 kernel 模板范围内
   （GLM5 是 H=64、D=8192、hidden=4096）。
2. **MLA 只复用 cache 写入（#12）**；注意力本体要从「KPool 稀疏 MLA」换成「稠密 Gated MLA + 输出门」。
3. **MoE 内核复用路由，但 FFN 要加 SiTU + Latent MoE**。
4. **KPool（#07/#09/#10/#19）和 mHC（#13/#14/#15）在 K3 上完全用不到**，可以认为这部分投入
   不被 K3 复用。
5. **新增工作**：SiTU-GLU、Latent MoE、AttnRes、Gated MLA 输出门、MoonViT3d、MXFP4（见量化文档）。

## 5. 待确认

- KDA kernel 对 **H=96 / D=12288** 的支持（可能需要补 `ah_*` 模板或分块）。
- K3 KDA 的 state layout（FLA `transpose_state_layout=True`）与 DLC 统一后的 `[S,H,Dv,Dk]` 是否一致。
- AttnRes 用 native 还是新算子（先 profile 其耗时占比）。
- MoonViT3d 是否需要 #17 那类 vision Q/K RMSNorm。
- K3 的 `routed_scaling_factor=1.0`、`num_expert_group=1` 对 MoE 内核的边界影响。
