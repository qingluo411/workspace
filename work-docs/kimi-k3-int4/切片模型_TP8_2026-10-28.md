# Kimi-K3-INT4 单机 8 卡 TP8 切片模型

## 1. 产物

- 路径：`/data/models/Kimi-K3-INT4-Slice8-TP8`
- 真实权重切片，不是随机初始化或 dummy checkpoint。
- 25 个 safetensors：1 个 global shard + 24 个 layer shard。
- 186,276 个 tensor，385,525,205,760 bytes（359.05 GiB）。
- TP8 每卡裸权重约 **44.88 GiB**；64 GiB TYD 单卡剩余约 **19.12 GiB**。

该每卡权重预算与完整 K3 在 TP32 下的平均权重预算（约 47.4 GB/rank）接近，因此可作为
单节点 TP8 的完整部署代理，用于加载、KV cache、算子、图和 API bring-up。

## 2. 切片规则

保留原模型连续前缀层 **0..23**：

- 24 / 93 层，约四分之一深度。
- 1 个 dense 层（layer 0）+ 23 个 MoE 层。
- 18 个 KDA 层 + 6 个 MLA 层，保持原本 3:1 的 KDA/MLA 比例。
- 保留 `attn_res_block_size=12`，包含 layer 0 与 layer 12 两个 AttnRes block 边界。
- 每层 hidden=7168、896 routed experts、16 selected、latent=3584 等规格完全不变。
- MLP/attention/MoE 的所有权重名和 tensor shape 不变，仅裁剪 layer 编号 >=24 的权重。

新 config 的关键字段：

```text
num_hidden_layers = 24
first_k_dense_replace = 1
linear_attn_config.kda_layers = [1,2,3,5,6,7,9,10,11,13,14,15,17,18,19,21,22,23]
linear_attn_config.full_attn_layers = [4,8,12,16,20,24]
attn_res_block_size = 12
num_nextn_predict_layers = 0
```

`quantization_config.ignore` 从 1,558 项裁剪为 490 项，已移除所有 layer >=24 的条目；
所有 61,824 个 routed-expert packed/scale/shape 三元组完整保留。

## 5. 与原模型的路径覆盖差距

这个切片保留了模块类型和单层规格，但不是原模型的完整执行子图。以下差距必须明确：

| 维度 | 完整 Kimi-K3 | 当前切片 | 影响 |
|---|---|---|---|
| 层实例 | 93 层（0..92） | 24 层（0..23） | layer 24..92 的实例不会执行；不能声称覆盖全部深度路径 |
| AttnRes block | 8 个 block | 2 个 block（layer 0、12） | 只覆盖 block_write_idx 0/1；后续 block 索引和 `num_blocks=8` 分支不覆盖 |
| KDA 层 | 69 层 | 18 层 | 模块类、head 数、单层 shape 相同，但实例数量和总层数不同 |
| MLA 层 | 24 层 | 6 层 | 模块类、q/kv LoRA、NoPE、output gate 相同，但实例数量和总层数不同 |
| MoE 层 | 92 层 | 23 层 | 896 experts、top-16、router、latent 规格相同；所有 expert 权重都保留 |
| dense 到 MoE 边界 | layer 0 dense，layer 1 起 MoE | 相同 | 该分支已覆盖 |
| routed-expert W4A16 | 92 层 x 896 experts | 23 层 x 896 experts | 量化格式、packed/scale/shape 路径相同，但层数减少 |
| 视觉塔 / projector | MoonViT3d + projector | 权重和 processor 都保留 | 只有实际图片/视频请求才会走视觉路径；纯文本测试不覆盖 |
| MTP / 内置投机层 | 原 config `num_nextn_predict_layers=0` | 同样为 0 | checkpoint 本身没有内置 MTP 路径，不属于切片遗漏；外部 draft 模型不在切片内 |
| 运行时模式 | prefill/decode、chunked prefill、prefix cache、Graph/eager、PP/EP/DP/DCP 等 | 模型文件本身不固定这些路径 | 必须通过独立测试矩阵覆盖，不能仅凭切片存在就认为已覆盖 |
| TP32 拓扑 | 4 节点 x 8 卡的跨节点 TP32 通信/切分 | 单机 TP8 | 仅模拟 TP32 的每卡权重预算，不覆盖 TP32 rank 布局和跨节点集合通信 |
| 输出语义 | 完整模型 | 前缀层切片 | 不是蒸馏模型，输出 token/精度不能代表完整 K3；只能用于部署链路验证 |

结论：

- **已覆盖**：所有主要模块类型、dense/KDA、MoE/KDA、MoE/MLA、Latent MoE、SiTU、W4A16 routed-expert、AttnRes 基本分支、final norm/lm_head、视觉权重与 processor。
- **未覆盖**：完整 93 层实例、后续 AttnRes block、TP32 跨节点拓扑、所有运行时模式、视觉实际前向和完整模型输出语义。
- 如果验收目标是“所有深度实例和所有运行时分支”，必须使用完整 32 卡模型；当前切片只作为单机部署和模块级适配代理。

## 6. 容量与使用方式

容量核算满足单机 8 x 64 GiB：

```text
weights / rank      44.88 GiB
remaining / rank    19.12 GiB
```

按 4K 上下文估算，每请求额外的主要 cache：

| cache | 每请求 |
|---|---:|
| 18 层 KDA recurrent state（FP32, H=12） | 约 13.5 MiB |
| 18 层 KDA conv state（BF16） | 约 0.5 MiB |
| 6 层 MLA latent cache（576 x BF16 / token） | 约 27.0 MiB |

8 并发、4K 上下文的模型 cache 约 0.33 GiB，剩余的主要是 activation、workspace 和
allocator 碎片。

剩余空间可用于 KDA recurrent/conv state、MLA latent cache、activation、workspace 和
allocator 碎片。建议先用 `--enforce-eager --max-model-len 4096` 验证，再开 graph。

当前限制：

1. 这是原模型的前缀层切片，不是蒸馏模型，输出语义不代表完整 K3；适合验证加载、显存、
   算子、图、并行、API 和多模态预处理，不用于精度评测。
2. DLC K3 模型入口/KDA/MoE/MLA/AttnRes 适配已完成首版；真实权重当前可在本切片上
   启动并完成单请求 prefill/decode，但仍需扩展到完整 93 层和 TP32 目标机。
3. 若后续需要更接近完整模型的行为，可另建“全 93 层、裁剪 experts”的深度保留变体；
   本次优先保证每层规格、层型比例和 TP8 本地 KDA 几何完全一致。

## 7. 后续目标启动参数

完成 K3 DLC 后端后，建议的首轮命令形态：

```bash
vllm serve /data/models/Kimi-K3-INT4-Slice8-TP8 \
  --served-model-name Kimi-K3-INT4-Slice8 \
  --tensor-parallel-size 8 \
  --enforce-eager \
  --trust-remote-code \
  --max-model-len 4096 \
  --max-num-batched-tokens 4096 \
  --max-num-seqs 8 \
  --gpu-memory-utilization 0.90 \
  --port 18005
```

首轮验收顺序：config/weight load -> 单请求 1 token -> 32/128 token -> prefill/decode 混合
-> KV cache 上限 -> eager 稳定后再测 `FULL_DECODE_ONLY` graph。
