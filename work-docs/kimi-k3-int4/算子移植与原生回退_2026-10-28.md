# Kimi-K3-INT4 DLC 算子移植与原生回退（2026-10-28）

## 1. 结论

1. GLM-5.3-Flash 的 KDA 适配可直接复用于 Kimi-K3。conv prefill/update、recurrent
   decode、chunk prefill、gated RMSNorm 已接到现有 DLC kernel；K3 的 packed decode
   和 full-rank gate 参数形式已补兼容。
2. DLC 没有对应实现的 K3 专有路径，优先按 PyTorch 原生组合替换：KDA state
   gather/scatter、MLA fused cache epilogue、q/kv RMSNorm、SiTU-GLU、AttnRes、
   compressed-tensors W4A16 MoE。
3. 单机 8 卡 TP8 切片模型已用 dummy 和真实权重分别完成端到端 prefill + decode。
   真实权重每 rank 47.56 GiB，真实单请求输出稳定、相同输入逐字一致。
4. 当前是功能优先路径，不是性能版本。native MoE、AttnRes 和 MLA epilogue 都保留为
   可替换 fallback；后续应以 DLC kernel 替换热点。

## 2. 切片覆盖范围

当前验证模型为 `/data/models/Kimi-K3-INT4-Slice8-TP8`，保留原模型连续前 24 层：

- 1 个 dense 层 + 23 个 MoE 层；
- 18 个 KDA 层 + 6 个 MLA 层；
- AttnRes 两个 block 边界；
- 896 experts、top-16、latent=3584、expert intermediate=3072 等单层规格不变。

因此本页可以证明上述模块类型和单层 shape 已进入实际执行路径，但不能替代完整 93 层、
TP32 跨节点、视觉前向和所有运行时模式的验收。

## 3. 算子映射

### 3.1 已有 DLC 算子，已移植接线

| K3 路径 | 上游实现 | DLC 路径 | 状态 |
|---|---|---|---|
| KDA short conv prefill | Triton/CUDA causal conv | `torch.dlc_kda_causal_conv_prefill` | 已接线 |
| KDA short conv decode | Triton/CUDA causal conv update | `torch.dlc_kda_causal_conv_update` | 已接线 |
| KDA recurrent decode | FlashInfer/Triton recurrent KDA | `torch.dlc_kda_recurrent_decode` | 已接线，H=12 TP8 几何通过 |
| KDA packed decode | K3 融合投影后的 packed qkv | 拆成 q/k/v 后调用 DLC recurrent decode | 已接线 |
| KDA chunk prefill | Triton chunk KDA | `torch.dlc_kda_chunk_prefill` | 已接线，H=12/C=64 通过 |
| KDA output RMSNorm + sigmoid gate | Triton/FLA gated RMSNorm | `torch.dlc_kda_rmsnorm_sigmoid_gate` | 已接线 |
| MLA prefill attention | FA/CUDA MLA prefill | `DLCFlashAttnPrefillBackend` + DLC flash attention | 已接线 |
| MLA latent cache 基础写入 | CUDA fused cache op | DLC 已有 `dlc_vllm_concat_and_cache_mla_`，当前 K3 融合 epilogue 先走 native | 可继续融合 |

### 3.2 上游专有、当前用 PyTorch 原生组合替换

| K3 路径 | 缺失原因 | 原生实现 | 验证 |
|---|---|---|---|
| KDA initial-state gather | 当前 DLC torch 无 `dlc_kda_state_gather` | `index_select` + mask `where` | dummy TP8 prefill 通过 |
| KDA state scatter | 当前 DLC torch 无 `dlc_kda_state_scatter` | `index_copy_` | 语义测试已接入，待独立 kernel 单测 |
| MLA decode q-concat + RoPE + latent cache insert | 仅有 CUDA `_C.fused_kimi_k3_mla_decode_q_concat_kv_cache_insert` | GPT-J RoPE + `cat` + `index_copy_` | CPU parity 通过，dummy TP8 decode 通过 |
| MLA prefill key-concat + RoPE + cache insert | 仅有 CUDA fused op | 原生 RoPE、`cat`、cache `index_copy_` | CPU parity 通过，dummy TP8 prefill 通过 |
| MLA chunk context KV concat | 仅有 CUDA fused op | `torch.cat` | 已接线 |
| q/kv 双 RMSNorm | 只有通用 DLC RMSNorm，无 K3 q+kv 融合接口 | FP32 variance + `rsqrt` + weight | 单测通过 |
| SiTU-GLU | DLC MoE activation 集不含 SiTU | `beta*tanh(gate/beta)*sigmoid(gate)`，可选 linear beta | 单测通过 |
| AttnRes | 上游为 Triton/CUDA 13 native kernel | residual bank 更新 + softmax 混合 + output RMSNorm | CPU 副作用/数值测试通过 |
| compressed-tensors W4A16-G128 routed MoE | DLC 现有 W4A16 MoE 路由接口与 vLLM 已选 top-k 接口不直接匹配，且 activation 不含 SiTU | packed INT4 按 expert 解包/反量化，逐 route 做 SiTU-GLU + down projection | 真实 checkpoint 单 expert 反量化一致；DLC 合成 MoE 一致 |

### 3.3 CUDA/Triton/CuTeDSL 路径的处理

以下路径不属于“替换单个算子”，当前直接禁用或绕过：

- CuTeDSL K3 latent-MoE tail fusion；
- 低延迟 KDA projection overlap / GEMM+RS+AR；
- DeepGEMM MegaMoE；
- FlashInfer KDA prefill、FlashKDA；
- CUDA stream/event 双流 overlap；
- `torch.compile`/Graph 路径（当前验证统一 `--enforce-eager`）。

`vllm_cl/patch/models/patch_kimi_k3.py` 在模型初始化阶段关闭这些路径，并把 MLA prefill
切到 DLC backend。

## 4. KV/state 与设备兼容

真实 K3 不能使用上游“一个大 backing tensor + 每层 storage offset view”的缓存布局：
DLC kernel 要求每层 cache 从 storage offset 0 开始且可连续搬运。

本轮补齐：

- attention KV 继续每层独立、offset-free 分配；
- KDA `MambaSpec` 走 split state pool：conv state 和 recurrent state 各自
  `[num_blocks, ...]` 独立连续分配；
- vLLM 为统一混合页大小而加的 Mamba page padding 不写入 split pool；该 padding 只用于
  调度器块记账，KDA kernel 实际消费的是独立 state tensor；
- `MambaBase.bind_kv_cache` 增加 split-pool 绑定校验；
- DLC 无 `torch.uint64`，Mamba copy pointer buffer 改用同宽 `int64` 承载地址位模式；
- MLA backend 补 `get_kv_cache_block_dim() == 0`，恢复 KVBlockZeroer 的 DLC 零页路径。

相关文件：

- `vllm_cl/worker/mamba_cache.py`
- `vllm_cl/patch/patch_mamba_state_pool.py`
- `vllm_cl/worker/dlc_model_runner.py`
- `vllm_cl/patch/patch_mla_attention.py`

## 5. 权重加载修正

compressed-tensors checkpoint 的 expert packed weight 是 `[out, pack(in)]`，vLLM 的
`RoutedExperts` 只在 quant method 运行时类名为 `CompressedTensorsWNA16MoEMethod` 时执行
转置。native 子类保留该运行时类名，因此加载后参数布局为：

- `w13`: `[experts, pack(hidden), 2 * intermediate_per_partition]`
- `w2`: `[experts, pack(intermediate_per_partition), hidden]`

native 反量化直接读取该布局，避免额外复制整层 expert 权重。

真实切片已加载完成：25 shards、每 rank 47.56 GiB，加载耗时约 1334 秒（ZFS + 8 rank
同步装载）。

## 7. 已知差距

1. native MoE 是逐 token、逐 expert 解包和矩阵乘，性能远低于融合 kernel，只适合功能验证。
2. DLC 已有 symmetric G128 W4A16 MoE 低层 kernel，但还缺“接收已选 top-k/scores + SiTU”
   的接线层，尚未替代 native MoE。
3. K3 MLA 的 FP8、`fp8_ds_mla`、ds_mla 变体尚未提供 native fallback；当前只覆盖 BF16
   KV cache。
4. KDA speculative decode、RecoverSSM、ReplaySSM 未启用。
5. Graph/compile 未验证；当前所有结论均来自 eager。
6. 视觉塔尚只验证权重加载，未验证图片/视频实际前向。
7. 切片不覆盖完整 93 层、8 个 AttnRes block、TP32 跨节点通信和完整输出语义。
