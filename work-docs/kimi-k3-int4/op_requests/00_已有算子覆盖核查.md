# Kimi-K3-INT4 算子覆盖核查（2026-10-28）

## 1. 核查目的

回答两个问题：

1. 当前 K3 native 回退中的哪些路径已经有 DLC 算子，可以直接接入而无需提单？
2. 哪些路径虽然有部分算子可以组合，但仍存在明确的 kernel 数、ABI 或性能缺口，值得提交需求？

## 2. 核查结论

| K3 路径 | 当前实现 / 可用算子 | 覆盖结论 | 本批动作 |
|---|---|---|---|
| KDA causal conv prefill | `torch.dlc_kda_causal_conv_prefill` | 已覆盖 | 不提单 |
| KDA causal conv update | `torch.dlc_kda_causal_conv_update` | 已覆盖 | 不提单 |
| KDA chunk prefill | `torch.dlc_kda_chunk_prefill` | 已覆盖 | 不提单 |

| KDA packed decode | `dlc_vllm_recurrent_gated_delta_rule_packed_decode` 仅支持 GDN 语义 | 入口存在，K3 gate/beta 语义不匹配 | 扩展 [#06](06_dlc_kimi_k3_kda_packed_decode.md) |
| Latent MoE tail | 无 | 缺失，但与集合通信、up-projection 和 shared expert 耦合 | 暂缓，待 #01 后 profile |
| MLA output gate | 普通 elementwise `sigmoid + mul` | 当前不是主要瓶颈 | 暂不提单 |
| MoonViT3d | 通用 visual ops / attention | 文本路径尚未验收视觉前向 | 暂不提单 |

## 3. 对已覆盖算子的说明

### 3.1 KDA 线

GLM-5.3-Flash 的 KDA 适配已证明可复用于 K3：

- conv kernel：`short_conv_kernel_size=4`、SiLU、三路 q/k/v；
- chunk/recurrent kernel：`Dk=Dv=128`、bounded sigmoid gate、in-kernel q/k L2 norm；
- RMSNorm gate：`head_dim=128`、sigmoid activation。

TP8 下 K3 每卡 `H=12`，已经落在现有 kernel 的已验证几何范围内。

### 3.2 KDA state pool

GLM 期初在“打包 Mamba 页 + 非连续 dim0 view”上测到 `index_select` / `index_copy_`
掉入 host 慢路径。K3 当前通过 split state pool 保证每个 state 从 storage offset 0
连续分配，因此 native 索引没有该退化条件。

若后续 TP32、长上下文或 graph capture 显示 gather/scatter 仍是热点，再按 GLM #05
的形式重新提交；本批不重复占用算子组排期。

### 3.3 MLA cache 写入

`dlc_vllm_concat_and_cache_mla_` 的输入是已经算好的 `kvc`、`kpe` 和 slot mapping，
不包含：

- q RoPE；
- k_pe RoPE；
- decode 的 `mqa_q = [ql_nope | q_pe]` 拼接；
- prefill 的 full-K 输出。

K3 native 目前每层需要多次 elementwise、concat 和 cache 操作。请求 #03/#04 不是重复
cache op，而是把 K3 的上游 CUDA fused epilogue 完整映射到 DLC。

### 3.4 RMSNorm

K3 MLA 的 q/kv norm 是两个独立二维张量，宽度分别为 1536 和 512。现有 DLC RMSNorm
可以逐个调用覆盖，真正的收益只是节省一次 launch；在 MoE 和 AttnRes 尚未收敛前不单提。

### 3.5 W4A16 MoE

现有 `dlc_vllm_fused_moe_w4a16_awq_col_major` 及 symmetric col-major 子内核已经覆盖：

- int32 packed weight；
- group scale；
- `[hidden, colpack(out)]` col-major 布局；
- G128 分块。

不能直接复用的部分：

- vLLM 在调用 quant method 前已经完成 top-k，传入的是 `topk_weights/topk_ids`，
  现有 API 仍接收完整 `gating_output` 并在 kernel 内路由；
- K3 activation 是 SiTU，不是 silu/swiglu-limit；
- K3 routed expert 输入维度是 latent 3584，不是模型 hidden 7168。

因此 #01 定义为“扩展已有算子能力”：新增 prerouted 入口，底层复用现有 W4A16
col-major 子内核。

## 4. 尚未纳入本批的候选

| 候选 | 暂缓原因 |
|---|---|
| Latent MoE tail：latent all-reduce + RMSNorm + up-proj + shared expert residual | 需要 TP collective 和 shared-expert 融合，先确认 #01 后 remaining time |
| MLA output gate 与 o_proj 融合 | elementwise 成本预计小于 MLA epilogue，待 graph/profile |
| K3 qkv projection + gate 融合 | 现有 linear backend 和 col-major 路径已可运行，优先保证 GEMM 正确性 |
| MoonViT3d 专用 attention / RoPE / patch merger | 当前只验证文本模型，视觉前向尚未进入验收 |

## 5. 需求映射

- #01：P0 routed MoE
- #02：P1 AttnRes
- #03：P1 MLA prefill epilogue
- #04：P1 MLA decode epilogue
- #05：P1 SiTU-GLU
- #06：P2 KDA packed decode
- #07：P2 / optional strict follow-up MLA context attention
