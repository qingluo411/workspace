> **进展更新（同日）**：首版 DLC 适配已落地，`/data/models/Kimi-K3-INT4-Slice8-TP8`
> 已用真实权重在单机 TP8 启动，并完成单请求 prefill、decode、10-token chunk prefill
> 和重复确定性验证。算子映射、原生回退和剩余差距以

## 1. 结论

1. 环境已按 GLM-5.3 发布后的新基线重建：基础仓库为最新 `main`，vLLM 为
   `upstream-v0.30.1rc0`，vllm-cl 为 `v0.30.1rc0`，两者均已切出
   `release-kimi-k3-int4`。
2. 模型是 2.802T 参数的 `compressed-tensors` W4A16-G128 INT4 checkpoint，实际
   checkpoint 为 1.383 TiB。**当前单机 8 x 64 GiB HBM 无法加载完整模型**，至少需要
   32 张 64 GiB TYD 才留有可用的 KV cache/activation 余量。
3. KDA 是最大的复用收益。GLM `release-glm53flash` 分支已有一套 DLC KDA
   monkey-patch，可移植到 K3。实机验证 TP8 的本地几何 `H=12, Dk=Dv=128` 在
   decode 和 chunk-prefill（C=64）均通过。
4. K3 不能直接走 vLLM 上游 `nvidia` 模型分支。DLC 平台不是 CUDA/ROCm，上游
   `KimiK3ForConditionalGeneration` 会落入 NVIDIA 实现，并依赖 CUDA stream、
   Triton、MegaMoE 和 CUTLASS/CuTeDSL 路径。
5. 首个功能闭环应聚焦：DLC K3 模型入口、KDA 移植、compressed-tensors W4A16 MoE
   接线、SiTU-GLU/Latent MoE、稠密 Gated MLA。AttnRes 可先用 native fallback。

## 4. 内存阻塞

简单容量核算：

- 当前 8 x 64 GiB = 512 GiB，仅能容纳约 36% 的裸权重。
- 24 x 64 GiB = 1.5 TiB，几乎不留 KV cache、activation、workspace 或 allocator 碎片余量。
- 32 x 64 GiB = 2.0 TiB，是更现实的最低部署档位。
- 当前主机内存约 1 TiB，也无法把 1.38 TiB checkpoint 全量 CPU offload。

因此本机只能做 config、权重 manifest、单算子、单层和 CPU reference 验证。整模型加载与
端到端验收必须在至少 32 卡的目标机执行。

为解除本地验证阻塞，已额外构建 24 层真实权重切片
`/data/models/Kimi-K3-INT4-Slice8-TP8`：359.05 GiB，TP8 每卡约 44.88 GiB，
可在单机 8 x 64 GiB 上作为完整部署代理。切片细节和验证见
`切片模型_TP8_2026-10-28.md`。

## 5. GLM-5.3-Flash 可复用矩阵

| 子系统 | 复用结论 | 依据 / 后续动作 |
|---|---|---|
| KDA causal conv prefill/update | 直接复用 | GLM `patch_kda.py` 已封装 `dlc_kda_causal_conv_*` |
| KDA recurrent decode | 直接复用 | TP8 本地 H=12 实机通过 |
| KDA chunk prefill | 直接复用 | H=12、C=64、N=64/256 实机通过 |
| KDA state gather/scatter | 直接复用 | 同为 FP32 `[pages,H,Dv,Dk]` 页状态 |
| KDA gated RMSNorm | 直接复用 | K3 仍是 sigmoid gate，D=128 |
| KDA full-rank gate | 需扩展现有接线 | 复用 kernel，核对 GLM patch 的 gate 参数和 fused-gate 路径 |
| KDA packed decode | 需新增接线 | K3 上游有 `fused_recurrent_kda_packed_decode`，GLM patch 尚无对应实现 |
| MLA latent cache 写入 | 可复用基础能力 | 512 latent + 64 rope；K3 是稠密 MLA，不使用 GLM KPool |
| MoE router | 可复用 | sigmoid + grouped top-k，基础结构与 GLM 同源 |
| W4A16 expert GEMM | 可复用 kernel，需新接线 | DLC 已有 symmetric G128 W4A16 MoE，但 vllm-cl 当前只接了 AWQ 类 |
| SiTU-GLU | 不可直接复用 | DLC MoE 当前仅支持 silu/swiglustep/gelu/relu2 |
| Latent MoE | 新增组合 | 3584 前置投影 + RMSNorm + routed experts + 3584 后置投影 |
| 稠密 Gated MLA | 需适配 | 复用 DLC MLA/cache，补 output gate，确认 q/kv LoRA 与 rope 布局 |
| KPool / DSA | 完全不用 | K3 无 KPool |
| mHC | 完全不用 | K3 是 AttnRes，不是四路残差 Sinkhorn |
| AttnRes | 需新增 fallback/算子 | 上游仅 Triton/CUDA 13 native kernel |
| MoonViT3d | 后置 | 先完成文本主干，再接视觉 |

GLM `release-glm53flash` 中的 `vllm_cl/patch/patch_kda.py` 是最重要的参考实现。它已覆盖：

- 三路 conv weight 合并与 `[4,D]` 布局缓存；
- conv prefill/update；
- recurrent decode；
- chunk prefill；
- state gather/scatter；
- gated RMSNorm；
- TP 状态索引的 packed 表示。

移植时需要把安装目标从 `vllm.models.glm5next.common.kda` 改为
`vllm.models.kimi_k3.nvidia.kda`，并处理 K3 的 full-rank gate 和 packed decode。

## 6. KDA 实机验证

脚本：`work-tests/kimi_k3/probe_kda_shapes.py`

| 几何 | 结果 |
|---|---|
| decode，H=12，Dk=Dv=128 | 通过；out_err 6.19e-4，state_err 9.73e-3 |
| chunk，H=12，N=64，C=64 | 通过 |
| chunk，H=12，N=256，C=64 | 通过 |
| chunk，H=96，N=16/32，C=32/48 | 通过 |
| chunk，H=96，N>=16，C=64 | 60 秒内不返回，外部 timeout 后进程退出才恢复队列 |
| chunk，H=64，N=16，C=64 | 通过 |

解释：

- K3 在 TP8 下每卡 KDA head 数为 12，因此现有 kernel 的生产几何已通过。
- H=96 是未做 TP 的完整 head 数；该几何不是当前 8/32 卡部署路径。
- 后续新增 KDA 单测应覆盖 H=12、C=64、T=1/64/256，以及 full-rank gate。

## 7. 上游 vLLM 入口问题

`vllm/models/kimi_k3/__init__.py` 的选择逻辑是：

```text
TPU -> 插件自定义
ROCm -> amd 实现
其它（包括 DLC） -> nvidia 实现
```

NVIDIA 实现会直接触发以下 DLC 不可用能力：

- `torch.cuda.Stream/Event` 和多流重叠；
- Triton KDA / AttnRes；
- DeepGEMM MegaMoE 和 CuTeDSL tail fusion；
- CUDA 专用 Marlin/FlashInfer/CUTLASS 后端选择。

因此 P0 需要新增 DLC 专用入口，或者在 vllm-cl 的模型 patch 中替换 K3 的
KDA/MLA/MoE/AttnRes 实现，同时保留 `KimiK3Config`、多模态 processor、权重映射和
tokenizer/parser。

## 8. 首批工作项

### M1：模型装配与权重审计

- 生成 K3 权重名到 vLLM 参数名的完整 manifest。
- 校验 92 个 MoE 层、896 experts、W4A16 G128 packed/scales/shape 的加载映射。
- 用 tiny synthetic config 构造不含大权重的 DLC 模型层，验证 shape、dtype、state spec。

### M2：KDA 移植

- 从 `release-glm53flash:vllm_cl/patch/patch_kda.py` 移植 DLC KDA。
- 目标模块改为 `vllm.models.kimi_k3.nvidia.kda`。
- 保持 full-rank gate，并处理 packed decode 或明确关闭该路径。
- 单测覆盖 H=12、C=64、conv state、recurrent state、gather/scatter。

### M3：W4A16 MoE + SiTU + Latent

- 为 `CompressedTensorsWNA16MoEMethod` 增加 DLC OOT 实现。
- 把 `w13/w2` packed weights 转成 DLC rowpack/col-major 布局。
- 将 symmetric G128 接到 `dlc_vllm_fused_moe_w4a16_*`。
- 给 DLC MoE kernel 增加 SiTU-GLU 激活。
- 用 PyTorch 实现 latent down/norm/up，先保证功能，再考虑融合。

### M4：Dense Gated MLA 与 AttnRes

- 在 DLC MLA backend 上核对 q_lora、NoPE、rope64、v128 和 output gate。
- 为 AttnRes 增加纯 PyTorch/DLC native fallback，先移除 Triton 依赖。
- 复现 GLM MLA cache 写入路径，不引入 KPool。

### M5：32 卡整模型验收

- 先 `--enforce-eager` 单请求正确性。
- 再做 chunked prefill、decode、多并发和 graph。
- 量化基线至少包含 BF16 reference 子集、token 一致性、长上下文和 NaN 检查。

## 9. 当前阻塞

| 阻塞 | 影响 | 处理 |
|---|---|---|
| 本机只有 8 卡 / 512 GiB HBM | 无法加载 1.38 TiB 权重 | 申请至少 32 x 64 GiB 目标机 |
| DLC 被上游 K3 当作 NVIDIA 平台 | 模型入口触发 CUDA/Triton | 新增 DLC 专用模型路径或 patch |
| DLC MoE 无 SiTU | K3 routed/shared FFN 语义不符 | 新增 kernel 分支和单测 |
| compressed-tensors WNA16 未接 DLC | 模型加载会选 CUDA WNA16 backend | 新增 DLC OOT quant method |
| AttnRes 仅 Triton/CUDA native | 每层 residual 混合不可执行 | 先 native fallback |
| 无 32 卡之间的 DLC 集合通信实测 | TP/EP 拓扑未定 | 与集群组确认拓扑和 DLCCL 版本 |
